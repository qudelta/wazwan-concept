Linear regression vs logistic regression · 1 of 2

Why not fit linear regression to 0/1 labels?

Same binary labels, two models

{{stack:demo}}
Linear regression

Predicts values from {{stat:demo_min}} to {{stat:demo_max}}: not valid probabilities, and a straight line ignores the S-shape.

Logistic regression

Squeezes the same linear score through the sigmoid: every output lies between 0 and 1.

What we want
P(unstable | β, c/(γH), φ)
Illustrative one-feature data from the session notebook (180 points, random seed 42); the slope dataset has three inputs.
{{top:1}}
Logistic regression in four steps

Inputs → score → probability → class

1

Inputs

β, c/(γH), φ

Slope angle, cohesion term, friction angle.

2

Linear score

z = b0 + Σ bjxj

Any real number. Same form as linear regression.

3

Probability

p = 1 / (1 + e−z)

The sigmoid maps z into (0, 1).

4

Decision

p ≥ threshold ?

Yes → unstable · No → stable.

{{i:info}}“Regression” stays in the name because the model is linear on the log-odds scale. The class comes from the threshold.
{{top:1}}
Step 1 · build a linear score

A weighted sum of the inputs, as in Session 03

For the slope-stability dataset
z = b0 + b1β + b2[c/(γH)] + b3φ
β

Slope angle

Steepness of the slope face.

15° – 65° · 11 levels
c/(γH)

Cohesion term

Dimensionless stability number: cohesion over unit weight × height.

0 – 0.30 · 7 levels
φ

Friction angle

Shear-strength parameter of the soil.

10° – 45° · 8 levels
{{i:sliders-horizontal}}z can be any number. The coefficients b are learned from the training cases; their sizes depend on units and scaling.
{{top:1}}
Step 2 · map the score to a probability

The sigmoid squashes any score into (0, 1)

p = σ(z)

{{stack:sigmoid}}
The sigmoid
p = 11 + e−z
  • z < 0 → p < 0.5
  • z = 0 → p = 0.5
  • z > 0 → p > 0.5

A model probability is an estimate. It is not automatically calibrated, and it is not a physical probability of failure.

{{top:1}}
Step 3 · what the coefficients model

Linear in the log-odds

Probability
p ∈ (0, 1)
p = 0.80

Bounded, so a straight line cannot model it directly.

Odds
p1 − p ∈ (0, ∞)
0.80 / 0.20 = 4 : 1

“Four times as likely to be unstable as stable.”

Log-odds · logit
log p1 − p = z
log 4 = 1.39

Unbounded in both directions, so a linear model can describe it.

{{i:warning}}A coefficient is the change in log-odds per unit of an input, others held fixed. It is an association in this numerical dataset, not a physical cause.
{{top:1}}
Step 4 · probability becomes a class

A threshold turns p into a decision

default rule: unstable if p ≥ 0.50
p < 0.50 → predict stable
p ≥ 0.50 → predict unstable
0.000.250.500.751.00
Lower the threshold

More cases flagged unstable: fewer missed unstable slopes, more false alarms.

Raise the threshold

Fewer cases flagged: fewer false alarms, more missed unstable slopes.

{{i:sliders}}0.50 is a software default, not a law of soil mechanics. Choose it on validation data, never on the test set.

Definitions before scores

Four metrics, four different questions

Recall (unstable) · sensitivity
Recall = TPTP + FN

Of all unstable cases, what fraction did we detect?

Precision (unstable)
Precision = TPTP + FP

Of all cases flagged unstable, what fraction really were?

F1 score
F1 = 2 · P · RP + R

One number that balances precision and recall (harmonic mean).

Balanced accuracy
BA = Recallunstable + Recallstable2

Gives both classes equal weight, unlike ordinary accuracy.

{{i:target}}Our priority today: do not miss unstable slopes. So recall for the unstable class comes first, with precision in view.

Two different thresholds: do not confuse them

One defines the target. One defines the decision.

The FOS label threshold

What “unstable” means

FOS < 1.0 → y = 1
  • Set before modelling, from engineering meaning
  • Changing it changes the target and the class balance
The probability threshold

When the model says “unstable”

p ≥ 0.50 → predict 1
  • Set after modelling, on validation data
  • Changing it trades precision against recall for the same target
Example
A slope with FOS = 0.95 is labelled unstable (y = 1). The model gives p = 0.42. At threshold 0.50 it predicts stable: a false negative. At 0.30 it would be flagged.

Key takeaways · carry this into every classification problem

A decision framework for classification

1Define the engineering meaning of each class
2Inspect class balance before choosing metrics
3Start from a baseline; stratify; tune only in training CV
4Choose metrics from the consequences of each error
5Select the model from the stated priority, not accuracy
6Report limits and where the result can generalise
The central lesson
High test accuracy is not proof of generalisation, or of engineering safety.

Appendix A5 · what each setting changes

Random forest mechanics

n_estimators

Number of trees. More trees stabilise predictions, at more compute.

max_features

Features considered at each split. Controls how different the trees are.

max_depth · min_samples_leaf

Limit tree complexity; can reduce overfitting.

class_weight

Gives the rare class more weight. Check recall and precision, not accuracy.

oob_score

Rows left out of a tree’s bootstrap give an internal estimate. It does not replace a held-out test set.

Random forest is not automatically superior. Compare on the same held-out data, with metrics aligned to the application.
